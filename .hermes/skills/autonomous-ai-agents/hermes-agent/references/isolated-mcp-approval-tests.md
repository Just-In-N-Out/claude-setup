# Isolated MCP and approval regression testing

Use this when a Hermes checkout under the real profile home fails before the target behavior because bootstrap probes its parent manifest or tries dependency preparation.

1. Inspect the traceback before changing tests. A refusal from tests/home_io_guard.py during pm.environments.payload_venv is a source-layout problem, not evidence that the approval change failed. Keep the failed logs and distinguish host execution from isolated validation.
2. Pin HEAD, all dirty source inputs and protected live config/launchers before creating a snapshot. Archive HEAD into an owned scratch directory, overlay the admitted current edits, and compare bytes/hash each overlay. Do not omit unaccounted-for dirty dependencies or claim an archive tests them. Never reset/stash the shared checkout.
3. Mount that disposable source at /repo in a private bubblewrap filesystem/network/process namespace. Mount only /usr, required account/certificate files, the installed venv and its interpreter distribution read-only; do not mount the live home, credentials, host Unix sockets or system bus. Bind private owned home/temp directories read-write. Clear the environment and pass an explicit installed HERMES_PYTHON. Cap memory/swap/CPU and elapsed time with a scoped supervisor.
4. Bind private temporary storage directly at /tmp rather than making /tmp a symlink. Approval path-canonicalization tests intentionally refuse symlinked cleanup operands; a symlink fixture creates a harness failure that must not be 'fixed' by weakening production checks. This /tmp is inside the private namespace and backed by the task scratch directory, not the host system temporary directory.
5. Execute the unchanged canonical scripts/run_tests.sh with bounded workers and explicit relevant test files. The archive lacks .git; its optional bytecode-precompile Git warning is separate from the runner's actual test results. Never treat a timeout, setup error or truncated runner headline as a pass.
6. Exercise the real installed MCP transport separately through the CLI callback and registered handler, using only an admitted synthetic source fixture. Drive actual modal selection and interrupt cleanup, count real RPCs, verify denied/cancelled requests dispatch nothing, preserve real Evidence, and publish success only after shutdown. Label automated input as test input, not human consent.
7. Reconcile tested-source hashes, protected config/launcher hashes and HEAD afterward. Remove owned snapshot/test bulk immediately, retaining small raw logs and bindings. A clean isolated suite does not mean the live-layout bootstrap bug is repaired or the already-running CLI has reloaded Python.
8. Make synthetic stdio peers answer `tools/list` even when testing only elicitation: the SDK may refresh tool schemas after the tool reply. Isolate request-callback cancellation from the SDK receive-loop task, or a fixture can close the transport and mask the intended lifetime failure.
9. Prove prompt lifetime with real locks and queues: require the synchronous worker to exit after RPC/elicitation cancellation while a neighboring prompt still holds the modal lock, then answer that neighbor and a subsequent prompt. Cancelling `asyncio.to_thread` or fencing only its eventual result does not retire its running worker. Perform bounded failure cleanup only after the exit oracle, never as the mechanism that makes it pass.
10. Before spending a final integration reserve on native decision validation, inspect every inherited assertion that consumes the affected native state and status label, not just its fixture helper. A new offered-choice field can stop exact-dictionary tests before they exercise the callback; an inherited blanket `expired` expectation can contradict its own still-pending event assertions and the required valid retry. Reconcile these contracts prospectively while preserving real stale/expired and neighbor controls. For HTML transports, compare descriptions against decoded rendered text rather than raw markup; classify failures at that assertion as fixture failures, not causal decision-boundary evidence. Preserve both oracle revisions and require independent adjudication of any changed expectation.
11. Keep Cartesian ingress matrices inside the canonical per-file time limit without weakening assertions. Repeated adapter/server/fixture initialization can dominate a large parameterized test before pytest prints causal tracebacks. When that happens, retain the timeout as incomplete evidence, preserve the original test bytes, and consolidate only repeated setup into bounded loops with fresh request/queue/event state for every case and explicit diagnostic labels. Keep the full payload matrix and inherited identities, then obtain a completed causal RED and unchanged-oracle GREEN within the original allocation; never extend caps or count partial F markers as proof.
