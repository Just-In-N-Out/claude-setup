# feature-dispatch: edge cases (lines moved whole from SKILL.md; load when one applies)

## Autonomous recommendation grants

- **Autonomous recommendation grants:** before acting on later results, record the named scope and termination condition in the handoff and each plan. For an away grant, use the stated expiry/return condition; for an explicit request to run named batches through merge without a duration, end the grant when those batches finish or Justin cancels—do not invent a time limit. Apply and record each safe recommended answer, then advance the approved pipeline without asking again. Keep event replies to one line. Carry explicit exclusions into every role brief, not only the planner's. Approval controls, compatibility proof, source ownership and explicit model choices still apply; a recommendation does not waive those gates or extend a release-specific waiver to later releases. A reviewed branch blocked only by a pre-existing proof gap stays held, with one shared lettered question for every branch blocked by that gap. Follow `references/away-and-recovery.md` for away-mode setup and expiry.

## Reusing an old copy

- **Reusing an old copy** (a stopped builder's worktree with no commits): write "bring it up to main with `git merge --ff-only main`" into the brief, never `git reset --hard main`. The merge needs no approval and refuses on its own if the branch has commits, while reset is flagged as destructive and sends Justin an approval prompt. An `isolation: "worktree"` agent's copy starts at the current `main`, so when `main` moved since the planner, `--ff-only <planner commit>` fails: the brief says to cherry-pick the earlier role's commits onto the copy, re-measure the base and read every literal base as `merge-base HEAD main` (web-compare builder; reviewers and verifiers just `git checkout --detach <head>`). Such an agent can't `cd` into another job's worktree for git (refused), but worktrees share the object store: give the other job's head SHA and have it read with `git show <sha>:<path>`, `git diff <base> <sha>`, or `git archive -o <scratch>/x.tar <sha>` then `tar -xf` (plain Read of the other worktree's files works too; web-panel planner).

## Evidence scope in corrective handoffs

- **Carry evidence scope through every corrective handoff.** Separate observed failures from source-predicted failures, completed checks from inherited reports, and missing plan tasks from new requirements. When a partial fix passes its targeted test but the full suite stays red, carry forward the exact remaining assertion and tested revision; do not report the whole defect fixed. Separate baseline-existing layout, introduced regressions and acceptance stronger than the approved requirement before assigning more implementation. Keep unrelated missing-proof release holds explicit without letting them block independent in-scope diagnosis or silently waiving them. A source-stage verdict is not full acceptance, while a finisher's green unit suite does not close omitted browser or compatibility checks. Give the next agent the exact reviewed and corrected revisions, the original probes and per-finding dispositions; let that agent independently execute the outstanding established gates. Do not turn the reviewer's suggested implementation into a dispatcher-designed fix or invent extra acceptance gates.

## A test that pins replaced behavior

- **Builder stopped on a test that pins intentionally replaced behavior:** have the agent identify the exact assertion, its independent controls and the stronger replacement oracle. If alignment is already an approved plan task, assign the missing task without another approval round. Otherwise record a narrow ownership clarification in the plan and brief only when the evidence shows direct alignment with an approved decision; return a genuine behavioral trade-off to Justin. Delegate patch application, test execution and commits even for a tiny prepared patch: manager-only mode has no test-edit shortcut. Require fresh independent review afterward, because an old assertion may also protect behavior the fix must preserve.

## Why is it paused

- **When Justin asks why work is paused or says to continue:** reconcile each named hold against the live list, latest result, durable plan and worktree before replying. Classify it as a missed transition, approval, quota, source dependency or unresolved policy/proof. Resume already-approved work immediately when its prerequisite is clear. For a genuine policy/proof hold, dispatch bounded read-only investigation or a scoped fix pass that can remove the uncertainty; do not leave it idle merely repeating the blocker. Keep release held where evidence or permission is still missing, and distinguish research from implementation in the reply. Use existing recommended-choice authorization only within its recorded scope; continuing work does not authorize silent font substitution, new navigation policy or permission bypass. Update the board in the same turn, then report what actually started and the specific remaining gate.
- **Re-read a brief generated by a script before dispatching it** (look-grouping, 2026-11-13): a Python slice-and-replace that templated one brief from another cut a line mid-word and joined it to the next heading ("…assumes from ea## What Justin asked") and left a list item as "px.". `grep -n '[^ ]## ' <brief>` and a look at each numbered list catch it.
