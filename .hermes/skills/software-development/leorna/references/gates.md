## Step 4: the gates

4. Run the gates and keep their real output:
   - **Host prerequisites:** on the Windows desktop (WSL Ubuntu), the planner checks `command -v go make gcc golangci-lint govulncheck` and `docker ps` and makes anything missing a plan question, not a builder discovery (current state in `leorna-control-plane-workflow.md`; 86bcm901a). `gcc` counts: control-plane `make test` runs `go test -race`, which needs cgo, and fresh WSL Ubuntu has no C compiler (`go env CGO_ENABLED` = 0; 86bcm901w). For Docker/buildx gates, bind `DOCKER_CONFIG` and `BUILDX_CONFIG` to role-owned scratch: even read-only qualification can write buildx activity files. Public Trivy operations also need an empty owned Docker config to avoid ambient Windows credential helpers; never repair shared Docker settings to qualify a gate. On macOS, before the control-plane gate, confirm the selected `realpath` supports GNU `--relative-to` and the selected Bash supports the workspace script's `mapfile -d`. macOS `/bin/realpath` and bundled Bash 3.2 failures are environment/baseline failures, not story regressions. Check already-installed Homebrew coreutils/`grealpath` and compatible Bash; select `coreutils/libexec/gnubin` and `/opt/homebrew/bin` ahead of system tools in the task's PATH when authorized. Do not change global PATH or patch unrelated repository code. Preserve failed receipts and prove the actual gate succeeds after selecting the tools; a working capability probe alone is not a passing project gate. Honor the story's outside-branch stop boundary before retrying.
   - Control plane: `make check` (needs `LEORNA_TEST_DATABASE_URL` and the `leorna-test-pg` container; confirm Postgres tests ran from a `go test -json` stream over the whole DB packages (`./internal/cloud/dbcheck ./internal/store/postgres ./internal/web`), read per test (Action plus that test's own Output), and fail any skip whose reason names `LEORNA_TEST_DATABASE_URL`: some Postgres-backed tests aren't named `WithPostgres` and skip silently without the DB (`newPackFixture`, `internal/web/packs_test.go`; 901a verifier). Give that `go test -json` run `-timeout 1800s`: on the loaded desktop `./internal/web` takes 9–10 min and hit the default 10 min limit (86bcxnykn builder). read each reason, 86bcm9284), since a whole-module `./...` stream also has ~16 env-gated skips elsewhere (Mongo, upstream network, tofu, ClickHouse in `internal/metric` and `internal/knowledge`, tool binaries) and build-tagged tests it never runs (901z review 6); 901w verifier); a filtered stream needs the same `-run` regex applied to the declared-test list, or ~200 tests look missing; when listing declared tests, filter `.claude` on repo-relative paths, since `claude -w` worktrees live under `.claude/worktrees/` (9019)) and `bash ./scripts/test-module-add.sh` (this script temporarily edits `go.work` and adds a deliberately broken module; 86bcm927y integrator). Before the first gate, resolve CI's current linter **and govulncheck** versions (CI pins both, e.g. `govulncheck@v1.7.0` while the Mac's default is newer) and inspect the effective Make recipe. Verify the intended compatible executable, then bind its checked absolute path through the supported child variable, for example `GOLANGCI_LINT="$verified_linter" GOVULNCHECK="$verified_govulncheck" make check` after setting both to checked paths. Merely installing or probing the right binary does not establish which binary Make selects through PATH. Keep the binding task-local; preserve a wrong-tool failure and rerun the unchanged canonical gate only after the tool-selection correction is established, without product/dependency or global-environment repair. Pass DB URLs to `systemd-run --scope` by exporting them (the scope inherits the caller's environment), never with `--setenv`, which a logged command line echoes with the password (86bccndx6 verifier 6). In a gate script that narrows PATH, read the `leorna-test-pg` password first (docker by absolute path) and abort if it is empty: an empty password fails every Postgres test with SQLSTATE 28P01, which looks like a branch failure. Before allocating an owned disposable DB, check the fixture's reset guard, and wait for a fresh Postgres container with `pg_isready -h 127.0.0.1` (TCP; the WSL desktop has no host `pg_isready`, so run it as `docker exec <container> pg_isready -h 127.0.0.1`): the image's init step runs a temporary socket-only server first, so a socket check passes too early and `createdb` fails with "the database system is shutting down" (86bccndx6 bring-main-1); current fixtures require a database name ending in `_test`. Never share/drop a sibling's DB. Run a base-commit baseline in a separate detached worktree with its own `_test` DB, never in the story worktree: new test files contaminate it, and two runs on one DB collide (store tests drop every table). Under heavy load (shared WSL desktop, load average 30–40), ClickHouse-backed tests can fail with "metric store unavailable" in a different test each run, and `TestQuickStartPickIsBoundedAndReleasesTheLockWithPostgres` can exceed its 1 s bound + 3 s limit (86bcm928t verifier: 4.27 s at load 20–27; so never run a role's own AC or mutant tests alongside its `make check`): rerun that test alone under `-race`, then the unchanged `make check`, and report every failed run with the passing one (86bccndx6 fixer 4). If it hits every ClickHouse test on every run, it is setup, not load: an owned ClickHouse container needs CI's service env from `.github/workflows/ci.yml` (`CLICKHOUSE_DB=leorna_metrics`, `CLICKHOUSE_USER=leorna_test`, its password, the pinned image); with `CLICKHOUSE_SKIP_USER_SETUP=1` it still answers `SELECT 1` and `/ping` but every test fails at Migrate (86bccndx6 fixer 5). `make check` also needs the network: `TestGoldenHCLPassesTofuValidate` (`internal/cloud/scaleway`) runs `tofu init`, which downloads the Scaleway provider and its SHA256SUMS/.sig from GitHub releases, so a GitHub outage (504) fails the test step and make skips lint, audit, secrets and build. It also skips silently when `tofu` isn't on the run's PATH (`exec.LookPath`), so `make check` exits 0 without it (`internal/cloud/scaleway` takes ~1 s instead of ~14 s; a copied gate script can carry a PATH entry for a deleted scratch bin): check `command -v tofu` first (if auto mode refuses downloading a release, copy an existing `~/.cache/*/bin/tofu` into the role's own bin and check `tofu version` is 1.12.6, run unpiped (a truncated 4 MiB copy segfaults with exit 139 and `| head` hides it; the good copy is 115,019,938 bytes); 86bccndx6 auditor 4, post-merge verifier) and confirm `--- PASS`, not SKIP, with a verbose run of that one test (86bccndx6 fixer 7). Keep the canonical make gate unchanged and use a separate `go test -v ...` invocation for verbose evidence; `GO='go -v'` places verbosity before the subcommand and is an invocation error, not a candidate failure.
   - Client: `make check` (about 2 min; set `export TMPDIR=$(cd ~/.hermes/cache/scratch/<dir> && pwd -P)` first), then `node --test scripts/*-ui.test.cjs`, then `make lint audit`. Lint with CI's golangci-lint version installed into a scratch bin (`GOBIN=<scratch>/leorna-bin go install github.com/golangci/golangci-lint/v2/cmd/golangci-lint@<CI version>`, then `PATH=<scratch>/leorna-bin:$PATH make lint audit`). **The scratch bin must be the first PATH entry, ahead of `/opt/homebrew/bin` and the gnubin directory** — `make lint` resolves the linter through PATH, so any earlier entry holding an older Homebrew build silently wins. Echo `golangci-lint --version` from the same PATH before trusting a lint result. A Homebrew build made with an older Go fails typecheck with "export data version … greater than maximum" on stdlib imports; those errors come from the tool, not the code, and the fix is PATH order or the `GOLANGCI_LINT=<abs path>` binding, never a code change. These Linux gates can't see CI's "Windows client executable" job (`go test` on windows-latest): Windows `t.TempDir()` holds the 8.3 short name `RUNNER~1`, which `filepath.EvalSymlinks` expands, and Windows reports file modes as 0o666, so a test that hashes a raw temp path against a canonicalised one, or asserts `Mode().Perm()`, passes locally and fails there. Also a "no absolute path leaked" check written as `strings.Contains(jsonText, rawRoot)` can never fail on Windows (JSON escapes backslashes; the saved folder is the long name): check the raw and resolved root, each as is and JSON-escaped. Grep for every such `strings.Contains(…, env.root|env.project)` and prove each with a Windows mutant that leaks through a new field or message (a `%q`-quoted path never matches the raw string either; 86bctmuwy review 7). Before a PR whose client tests changed, grep the new tests for these traps and run the changed packages natively on Windows (recipe in the next item) (86bctmuwy PR #32: 5 Windows-only failures, every local gate green).
