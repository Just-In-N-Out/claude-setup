## Step 4b: evidence by role

4b. **Collect ClickUp evidence while building**, following `clickup-evidence.md`:
   - **Planner:** make evidence capture a named build task. Map each acceptance criterion to the real state/result to demonstrate, the capture point and the durable artifact path; carry this into the builder brief rather than leaving it as a closing reminder.
   - **Builder:** save meaningful before-state screenshots before changing visible behavior, then capture each visible criterion and actual live/manual result as its check runs—not a reconstruction at hand-over. A capture driver that waits for an element after a form submit can shoot the pre-submit page when that element is already on it: mark the old page (`window.__beforeSubmit = true`) and wait for a loaded page without the mark (902a fixer 2). chromedp takes each action's arguments when the task list is built, so a `Navigate(base+x)` in the same `Run` as the `Location(&x)`/`Evaluate` that sets `x` goes to an empty URL (-32000): read in one `Run`, navigate in the next (901z builder). A desktop (Wails) panel needs no app window: a harness page of the shipped JS/CSS, the panel markup from `index.html`, a stub `window.go.desktop.Bridge` returning the real test result and an inline script clicking the real buttons, rendered by headless Chrome `--virtual-time-budget=5000` (`--dump-dom` for the height, then `--screenshot`), labelled a local rendering (86bctmuwy builder). For continuous chromedp recordings, serialize timer screenshots with document navigation and bound each capture; retries for detached-page errors alone can still hang. Go tests only pin markup, so prove a browser-only guard (`required`, a page script) with a chromedp probe added by `-overlay` to the package's own fixture: `ignore-certificate-errors` for httptest's TLS server, the `__Host-` session and CSRF cookies set with `network.SetCookie(name, value).WithURL(server.URL).WithPath("/").WithSecure(true)`; `Click` on submit runs real constraint validation and `SetUploadFiles` fires `change` (901z fixer 3), but `SetUploadFiles` with an empty list doesn't clear the input (`files.length` stays 1, no `change`): to imitate a cleared picker set `value=''` and dispatch a bubbling `change` (901z review 4); `FullScreenshot(&buf, q)` writes a JPEG unless `q` is 100, so check a capture's magic bytes before calling it `.png` (901z finisher); screenshot the same element the page check reads, since the Content library page's first `<table>` is the starter-packs table (`table:has(tr.item)` or `table:has(tr.variant)`), and byte-identical shots of two different states mean the wrong element (901z auditor 2), unless the page really renders those states the same (a refusal that doesn't echo input): compare the page state too, and report that as a UX finding (86bcm927y review 5). Use `~/.hermes/plans/leorna/evidence/<clickup-id>/`, screenshots `ac<n>-<what>.png` and per-head gate logs `gates-<sha7>.txt`. **One screenshot per AC (Justin, 2026-10-23: "take a screenshot for each AC because we are going to upload to clickup"):**
     - a visible criterion gets a capture of the real page or app result;
     - a criterion with nothing visual (a CI, CLI or timing check) gets a real terminal-window capture of its actual run, showing the command, output and exit code, plus its log. The recipe below is macOS-only; on the WSL desktop the capture is a rendering of that run's own log, labelled as such, made the way `feature-dispatch` references/ac-verification.md says (86bcm928h finisher).
       - **Terminal capture recipe (2026-10-23, 901u v2 builder):** open a dedicated Terminal window with `osascript` running `exec env -i HOME=… PATH=… TERM=xterm-256color PS1='$ ' bash --norc --noprofile` (without `TERM`, `clear` fails and the zsh prompt with the hostname stays on screen), and wait until the tab's `history` shows the `$ ` prompt (up to 90 s on a loaded machine) before typing, because a fresh tab's zsh startup races typed commands. Take the window id from the handle `do script` returns (`tab 1 of window id N`; return the tab object itself, since `as text` fails with -1700 after the window has opened), never `front window`, which can be an older window. Close it by id in a `trap` on every exit path, so a failed capture never leaves its window open. Wait for a new marker (one more `EXIT=` line or `$ ` prompt) before typing the next command, or it echoes into the running output (9019), and not for old text to vanish, and count the markers *after* `clear`: `history` sometimes keeps scrollback across `clear` and sometimes drops it, so a count taken before can never be exceeded and the wait hangs (901u v3 verifier). In AppleScript, read `history of <tab>` (`contents of <variable>` dereferences the variable instead of reading Terminal). Pass typed commands (and the launch line) as argv, not inside an AppleScript string, so quotes, `$(…)` and `^Test$` need no escaping: `osascript -e 'on run argv' -e 'tell application "Terminal" to do script (item 1 of argv) in tab 1 of window id ((item 2 of argv) as integer)' -e 'end run' "$cmd" "$wid"`. Capture with `screencapture -x -o -l <window id>` (on a locked screen it prints "Could not create image from window" and writes nothing while the commands still run: check `ioreg -n Root -d1 -a | plutil -extract IOConsoleUsers xml1 -o - -` for `CGSSessionScreenIsLocked` first and leave the PNG owed, 9019); Terminal silently clamps `number of rows` to the screen height (72 asked, 65 given, 945u; set `font size of tab 1 of window id N` to 9 first for ~76 rows, 9019), so before accepting any PNG check that its first command is on screen (even a ~30-line run can render a blank top row; retake it). Close the window with `close window id N saving no` (typing `exit` leaves it open, showing `[Process completed]`); after that, N can stay in `id of every window` with 0 tabs; confirm it closed with `{visible, count of tabs} of window id N` → `false, 0`, rather than retrying or touching other windows. Run `make -s` so make doesn't echo recipes with absolute paths. Pipe a `docker exec` step through `set -o pipefail; <cmd> </dev/null 2>&1 | cat`: on the TTY it can scroll every earlier command off screen, and pipefail keeps `EXIT=$?` the command's status, not cat's. The tab's `history` also holds the zsh preamble and the whole `exec env -i …` line: never put a DB URL, password or token on that line, and trim a saved log from its `$ clear` line (901u v3).
       - **Markdown or job-summary output:** render the real output before the screenshot (offline: goldmark from the Go module cache plus headless Chrome with a throwaway `--user-data-dir`), and label it a local rendering. Tests on raw Markdown can't see GFM autolinking: `name@1.0.0` rendered as a `mailto:` link.

     A staged screenshot that claims an unrun check passed never counts. Use real tools, the app or Justin's own permitted server for the live/manual run; missing execution stays **NOT VERIFIED** with its reason.
   - **Finisher:** reconcile the AC → test/result → artifact inventory before hand-over. Planned filenames are not collected evidence; name missing proof explicitly. Count mutants by distinct ID with their final outcome, not by summing a receipt's `SUMMARY` batches, which repeat re-runs (902a finisher: 31 runs, 27 mutants). Keep automated fixtures and headless/CDP journeys separate from operator acceptance. When Verify requires hands-on use or actual browser zoom, a passing fixture, viewport emulation, CSS scaling or a completion marker is not that proof; record the actual operator/browser state or leave the criterion **NOT VERIFIED** and acceptance-blocking. Draft the closing comment and attachment list, but **upload only when Justin says post**; a screenshot reminder is not permission to publish or change card status.
   - **Open every log before citing or attaching it and read its recorded exit code.** One head usually has several runs of the same gate: a first failure from a host-tool problem, then the passing rerun saved under a suffixed name (`gates-<sha7>-<fix>.txt`), which leaves the plain `gates-<sha7>.txt` holding the failure. Selecting evidence by filename alone attaches a failed gate as proof the story passed. Match each attachment to its `.json` receipt (`exit_code`) before it leaves the Mac. A gate step that greps the log it is writing (e.g. counting `--- SKIP`) must ignore its own echoed `$ ` command line, or it counts the pattern in its own command and fails with no real skip (945u).
