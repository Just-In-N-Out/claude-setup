# Figma to Bricks v2 (FigmaToBricksV2)

Justin's Figma plugin that converts any Figma design into a Bricks (WordPress) paste. Main folder: `~/Documents/FigmaToBricksV2`, branch `main`, private GitHub `Just-In-N-Out/FigmaToBricksV2`. Figma loads the main folder's `dist/`.

The project's standing rules and compact Status are in the main folder's `CLAUDE.md` (not in git); feature history is in HANDOFF and plan ledgers. Hermes sessions start in `~`, so it never auto-loads; this skill makes sure it's read and adapts its Claude Code worktree steps to Hermes. When this skill and that `CLAUDE.md` disagree, `CLAUDE.md` wins.

- Justin asks for a feature, fix or check on "the Figma plugin", "Figma to Bricks", "the plugin", or the Bricks paste
- Any work in `~/Documents/FigmaToBricksV2` or one of its `.claude/worktrees/*` copies

## Pitfalls

- **Separate Figma preservation from disposable test-folder cleanup.** Record the exact resource covered by a no-deletion instruction; do not silently broaden or narrow it. If normal browser/unit/corpus tests remove their newly created temporary folders, identify that specific operation early and ask for a narrow exception while independent implementation continues. Once granted, update the plan, brief and handoff and steer the live owner; do not leave an obsolete gate hold. Permission covers only verified run-created disposable folders and their generated contents—not Figma layers or temporary clones, existing folders, user/project source files, sibling artifacts, worktrees or branch cleanup. Preserve durable evidence outside disposable folders and keep unexecuted gates explicitly unverified. These scoped permissions belong in the task records, not as global user preferences.

- **Audit diagnostic exports before requesting them or calling them read-only.** Check document, temporary-node, store, selection, clipboard and network side effects: Save debug file reads the current selection and can create/remove temporary clones while exporting state pictures. Accept recording/inspection consent once, retain its exact exclusions in the plan and worker brief, and do not re-ask an already-resolved cleanup question. When no deletion includes temporary copies, exclude that exporter without modifying source to bypass the rule. Preserve the open output/runtime/selection and use only verified nonmutating observations. A UI screenshot is not a source snapshot, and a current-source export is not retrospective proof of the last conversion's input; if permitted evidence cannot answer the missing-source question, report that gap rather than claiming the fallback resolves it. Do not treat `pictures:false` as nonexporting: snapshot extraction still invokes text/vector SVG helpers. A separately approved safe metadata reader needs a closed read-only projection/capability, not the broad snapshot exporter.

- For card sizing, responsive spacing, hover-wrapper matching and motion changes, follow the adversarial recipes in `references/rendering-validation.md` before claiming geometry or corpus acceptance. Test replacement ownership and parent footprint as well as painted bounds; containment-only checks and a clean lint can miss collapsed pictures, compensated new content or deterministic pixel regressions.
- A negative-margin compensation can fix a hover wrapper's CSS flow while the responsive planner still counts its full drawn width. Trace minimum/content/keeps readers and compare computed phone padding at 375/360/320; a 3px width discrepancy can change a padding clamp and violate a ±1px motion requirement even when all leaves remain contained. Preserve the strict failing motion oracle and stop at the scoped adapt boundary rather than relaxing it.
- Figma's SES sandbox refuses the bundle when `import` is followed by `(`, `//` or `/*`, or when `<!--`/`-->` appears anywhere, comments included. `build.mjs` checks for this. Never end a comment line with "import".
- Tests run with `node --test` on `.ts` directly: only erasable TypeScript (no `enum`, `namespace`, or parameter properties).
- A bar painted inside an unpainted section frame becomes section → band → Container (`section.ts` `bandIR`): a rule marking "the section's Container" must look through bands, and a Figma wrapper's own max width wins over a widening rule after it. Give such rules a wrapped fixture variant; real headers are drawn this way (header-bar Task 4b: fixtures green, hydraulics unchanged). A child swapped into a laid-out fixture row before `snapshot()` keeps x/y 0 and becomes the row's first layer: give it the old child's x/y. A fixture for a design wider than 1440 needs every section frame at the design width (else the 1440-wide site-parts sections fold into one page section); assert the pattern is recognised before asserting an effect is absent, or the absence check passes vacuously. A logo frame filled by a same-size picture is no drawn logo (the picture becomes the frame's cover), so such a bar is never a header. A fixture page of only two sections must be drawn at least 1.5× its width tall (`page-frame.ts` `pageLike`), or `bandsOf` makes the whole page one section and section-level guards can't be reached. Normalise merges a frame wrapping one vector into a single vector named after the frame and keeps only the frame's own `vector.svg`: put an icon fixture's drawing on the outer node. In a free-drawn fixture frame, a rectangle spanning the whole frame becomes the frame's own fill after normalise (a "background layer stays a layer" negative needs an absolute child of an auto-layout frame). `designs.ts` `space()` turns the gap between two self-painted sections into a margin in the page colour: code that makes sections out of a painted frame's children must give those gaps the frame's paint, and assert the seams in Chrome (after-faq-sections AC2); every "is it painted" reader (`rhythm.ts` `paints()`/`edgeOf`) must also see paint a section got that way (`sectionIR` `behind`), and a gap that is really paint (a frame's padding a kept part shows) must be held inside the painting section before `rhythmOf` runs: `space()` drops free gaps at every boundary the rhythm sets, so fixing only the read still loses it. Overlap-based overlay assignment (`bandsOf`-style, default `bands[0]`) breaks for auto-layout flow children, which never overlap: probe any split-a-frame rule with a narrow flow child above, between and below the parts. A rule that decides with `siteFooter` and reshapes the list before `leaveOut` calls it again can disagree with it (the thin-bar path looks only directly above a bar ≤ `BAR_MAX`): keep the split only when the final call finds exactly the tail, and probe a 1px rule and a 120px+ wordless part between the columns and the © bar.
- Hand-built paste CSS: Bricks' Image with tag `figure` is inline-block (inside a link it gains a line box and the link's width cap: give it `display:block; max-width:none`); `object-fit: cover` can't crop a logo's transparent margins (clip the figure, scale the img to its ink); element custom CSS prints after its settings CSS, so a custom `@media (max-width:1024px)` overrides its own phone keys unless it has a min-width. Element controls print on `#brxe-<id>`, so a class's `:hover`/`:focus-visible` can't override them: put every property the class changes in the class (`.brxe-button.<class>`).
- Generic text fixtures use the builder option `family`, not `fontFamily`; `fixedText`/`segmented` default to 24px line-height. For per-layer diagnostics, assert final warning counts with distinct source IDs sharing identical names, targets and reasons, covering success and fallback; differing names hide message-based deduplication. Repeat diagnostic probes on page layers and rendered card/variant subtrees, including generated copies. Give a large-font ticker its actual single-line height/line-height before diagnosing marquee recognition. `text()` overwrites a passed `layoutSizingHorizontal` and the row builder never stretches a FILL child: set `{ ...text(…, { width: <row's rest>, inkWidth }), layoutSizingHorizontal: 'FILL' }` after. `normalise/infer.ts` reads a row's widest gap (≥ 40px, ≥ 2× the others, no picture) as an auto push, so a two-item row with one wide gap is never tight: use three items with equal gaps. An arrow icon beside a box's words makes the box the plugin's own page link (`page-links.ts`); a painted box ≤ 120px tall holding only one-line texts is a label box (its words a button's); an auto-layout column taller than its free-drawn section is read as placed. When a Chrome spill check fails on a new fixture, render it with the new marks stripped first: if it fails as drawn too, the fixture's widths are the cause. Probe a new rule with the designs that fool it: a go-word rule (`page-words.ts` GO) against nav menus and footer link columns (one item changes, its siblings don't); a rule on fixed or drawn widths with a free-drawn words + arrow group inside a row (without auto layout it infers a fixed-width row with no free room). A rule that leaves out items by counting alike siblings must also check the holder is that kind of group (a menu: every flowing item one line of words or wordless), or a mixed section column passes. Narrowing a rule to leave out a kind has its own blast radius: probe the common layout sharing that structure (a blog card's category pill beside meta words of its font and size looks exactly like tabs). `IRNode.parent` is the SceneNode a layer sits in, not its IR parent: reason about IR siblings through `walkIR`'s second argument or a carried ancestor path. A `copyIR` root comes back with `parent: null`, `placement: "flow"`, `parentFlow: null` and `sizing.w: "fill"`: geometry that needs its holder comes from the IR parent in the walk. To prove a new `payloadProblems` guard passes on main's output, put only the new `payload.ts` in a `git archive <main>` tree and run the unit suite and replays there (every fixture conversion calls `assertPayload`). Fixtures and corpus passing doesn't prove a new fatal guard can't fire on users' designs: grep every producer of what it refuses (for links: every link set after nodeIR, e.g. `phone.ts` band copies, `list-rows.ts`/`list-links.ts` PDF links) and probe each with a generic fixture. Moving an element's link to another IR node drops it from `emit/page-addresses.ts` (matched against `n.src.link`/`pageLink`): carry where it came from. A wrapper whose IR `flow` is null reads as zero room in `adapt/least.ts` (`least`, `reading`, `content`): judge it by the inner box holding the layout. A fixture testing "inside a box that clips" needs a clipping frame with a corner radius, a spill or a placed layer: `style/paint.ts` writes `overflow: hidden` only then. Fixture `snapshot()` never visits `targets`: call `snapshot(targetFrames)` first, or overlay/Navigate target frames keep relative boxes. Layers moved or replaced after `snapshot()` keep a stale `absoluteBoundingBox`: call `snapshot(roots, extra)` again before converting. Fixtures put the page frame at canvas (0, 0), real frames never sit there: a feature reading absolute geometry needs a probe with the root moved (e.g. x 3000, y −700). The builders' `text()` sets `absoluteRenderBounds` to the whole box unless `inkWidth` is given, so a rule reading Figma's render width needs fixtures with a realistic `inkWidth`. An adapt rule overriding CSS that emit builds outside `Style.parts` (a mark's CSS, Motion) holds only if emit writes that base CSS before the tier `@media` blocks: check the order first. A fixture adding an Open link or Navigate to an instance appends to its reactions (`[...(c.reactions ?? []), …]`): replacing them drops the main's While hovering. Recognition predicates read after `understand()` see the hover layers `planHovers` adds last, so compare decided outcomes (phone copies, split marks, showcase marks) instead. To prove a plan reader treats a wrapper like the unmarked layer, compare `planLayout(page, styleAll(page, scene), pageFacts(page))` least, width and row at every tier, and `content` only from tablets down (it throws at `fluid` on body text). A feature reading line geometry from a text box also needs a one-line text in a taller box: `styled()` takes `boxHeight` and `valign` (headline-marker; it shifts the SVG baselines as Figma draws them), while a FILL-height text still needs `layoutSizingVertical: 'FILL'` and `layoutGrow` set by hand. A multi-slide (Splide) fixture needs slides of different content lengths: Splide stretches every slide to the tallest, so a painted child that doesn't grow leaves a blank strip. An icon placed from a library is a frame around a vector with no paint of its own (and a circle button's paint is its backdrop): read its colour from its SVG drawing and its size from the drawing's bounds. Splide's `interval` runs from the start of each change (speed included), while Swiper's delay and Figma's After delay start after it ends. `normalise/infer.ts` `group()` runs `inferLayout` with default options on the CUT groups v2 makes, so a per-frame option passed down `inferLayouts`' walk never reaches them: gate such options on `n.figmaType !== CUT`. Normalise can't predict understand's section roles exactly (a frame spanning a free-drawn section is a band through `fullPart`, painted or not). A feature keyed on layers placed in a box must also be probed with them grouped (Cmd+G) or in a plain frame: the wrapper becomes the IR box, so shares and shapes land on it and phones drift while the design width stays exact. Count calls to action with `markCtas`'s whole predicate (`ctaLike`, no short tag in a chip row, `pillMiddle`): `ctaLike` alone takes a painted form field (words at its left) for a pill. Calls to action have two consumers, `markCtas` and `heroOf` → `heroButtons` (hides button-like layers in a hero on phones and copies them into a band): exclude a feature's own pills from both, and probe it as a hero's beside-media (a free-frame root with 2–3 sections placed at y, the picture an image layer).
