# Test, receipt and browser-measurement pitfalls (figma-to-bricks)

Moved out of SKILL.md "Pitfalls" on 2026-10-29 to keep the skill under Hermes' size limit. Read this before writing or running a receipt, a corpus comparison, a mutation run or a browser measurement.

- Compare decoded font-family names using Unicode default caseless matching (CSS C/F folding), not exact spelling, locale lowercasing, punctuation stripping or Unicode normalization. Keep original display spelling and significant quoted whitespace/opposite quotes. Exercise real visible loaded-family twins and distinct-name negatives; when using a compact folding implementation, verify its equivalence classes against the runtime Unicode version's authoritative CaseFolding data.
- Corpus current-font completeness must run independently of baseline-file intersection and baseline existence. Exercise the actual CLI exit branch with shared, empty and absent baseline fixtures; inject only capture data and filesystem paths, never diagnostics or exit logic. Verify missing, observed failed and expected/loaded-inconsistent states reject current-only files while complete controls pass and legacy report fields remain untouched.
- Hardened capture diagnostics can expose an existing missing font even when payloads, full HTML and every old report field remain byte-identical. Separate the new non-comparability finding from existing converter/v1 findings; preserve original reports and do not call all fonts matched merely because old loaded sets agree. If the missing family is declared on real positive-size content, do not silently narrow expectations to hide it or add an unapproved stand-in. When geometry disagrees with exported `opsz`, check automatic optical-sizing mode and the delivered binary's actual axes before requesting another font file: a weight-variable source can lack optical/custom axes. Preserve raw axis metadata separately from proven effective mode; a cross-size visual match is evidence to investigate, not permission to override an unobserved source setting. Runtime text replacements must copy resolved font longhands and variation controls: a valid family can have an empty computed `font` shorthand. Verify actual input/placeholder glyphs and an axis-loss control.
- To prove clipping, keep frame-size geometry as a separate claim and measure paint/hit-testing outside a full-bleed zoomed child. A same-fixture overflow-visible mutation must fail the strengthened checker while preserving frame dimensions and zoom; pseudo-element paint needs screenshot pixels, not a fictional DOM node. For text visibility, Range area, opacity and hit ownership do not prove glyph paint: use a calibrated ink/pixel oracle with phone-only transparent color/text-fill mutations and visible outline/gradient/inline controls. Disable transitions in a never-zooming negative control so a still-running transition cannot masquerade as its terminal state.
- Release bundle verification: only `dist/code.js` embeds the BUILD literal; the panel receives it through the plugin's init message. Do not reject a fresh `ui.html` for lacking that string. For strong proof, reproduce both bundles in memory with esbuild `write:false` and the exact build options/UI inlining, then compare full bytes and hash the actual main dist files without overwriting them.
- **A browser test meant to kill a CSS-formula mutant, or whose layout depends on exact widths (a row drawn exactly as wide as its items), must reach the case in Chrome, not just in the plan:** fixture text widths are declared Figma numbers, but Chrome draws the real font (Arial "Arrange a longer stay" declared 193.94 renders 153), and a fixed-width holder beside a picture stacks to 100% on phones. Measure the real word widths and holder width first, set the fixture's declared widths to them, and run the mutant on a scratch copy to see the browser case fail (the builders' half-an-em widths run far narrower than Google-loaded Inter: 66 declared vs 108 drawn). To test a layout-plan change for a class of rows, also build the fixture "as drawn" with the same ids (understand, delete the new marks, then style → adapt → emit) and assert the plan's row shapes and tier gaps against it, plus `least(row) ≤ width(row) + 1` wherever the plan keeps a row: paste-only checks miss plan-only mutants.
- Browser tests and `snap` drive the system Chrome. One showcase test can flake under a busy Chrome; re-run it before calling it a regression. A live-host check (web-capture AC14, "a shown picture has no bytes") can fail on Node's passing `fetch failed` (30 of 38 pictures, twice in 20 min): re-fetch the listed URLs with Node and capture both heads back to back before blaming code, keeping the failed receipts (web-capture fixer 6).
- A resumed final gate with missing slider/pagination DOM and empty loaded-font sets is not a source verdict: preserve that raw run, verify exact source, and rerun the unchanged gates before editing layout or weakening assertions. Compare expected loaded families even when `failed: []`; matched same-HTML recaptures must retain their original provenance.
- Verify animation resume with bounded measured progress, not one fixed 100ms sample: Chrome can report `animation-play-state: running` before its animation clock advances. Prove the check still fails with a permanently paused track.
- `npm run corpus` exits 1 whenever main itself has "Worse than v1" items (18 on 2026-10-20), so its exit code isn't the gate. Save the report and copies of `corpus/out/v2/*/bricks.json` before Task 1; at the close, `cmp` the pastes and diff the lint lines and the "Worse than v1" list. Page scores move by up to about 0.002 between runs of byte-identical pastes (Chrome's rendering noise; design gave 0.4428–0.4451 for one paste).
- Copy `corpus/report-v2.json` alongside the baseline pastes before source edits: the next corpus run overwrites it, and console totals omit per-check findings, section scores and font status. If an animated section's score changes, compare its subtree and freeze finite/infinite animations consistently in both saved renders before declaring a regression or improvement. `document.getAnimations()` sees only registered effects: native entrances awaiting timers or offscreen observers can remain hidden. Observe activation of currently rendered eligible targets before settling finite effects, restore scroll, and keep ordinary capture settling separate from live timeline proof.
- If a baseline font failed but the final loaded it, keep both original reports and label the comparison non-comparable; rerender the saved identical HTML in matched pairs with fonts loaded, comparing full lint/height at every affected width. Do not overwrite the baseline or call its reports identical. Keep screenshot RGBA in Buffers/typed arrays, not JavaScript number arrays, to avoid exhausting Node's heap on tall pages.
- Use one active Chrome page for sequential saved-HTML recaptures, or bound every frame-settling wait. Multiple headless tabs can stall requestAnimationFrame-based settling; assert exact HTML equality, expected loaded-family sets and full-width findings before judging pixel differences, preserving failed captures separately. For native Nav checks at several widths, initialize a fresh document at each tested width, or qualify its native resize handler first: the renderer suppresses full Bricks startup, so resizing after desktop initialization can leave the close control's parent at inline display:none. Prove the distinction with plain/compound controls and the archived native bricksToggleDisplay before blaming emitted source (dark-structure-recognition fixer6).
- On a resumed build, verify the full baseline report really exists, not just its console log. If missing, re-run the exact pre-feature commit from a scratch archive and label the resulting full report **reconstructed**; keep the original saved pastes/log separately and compare both. Never describe the reconstructed report as the original capture.
- `corpus/out/v2/*/bricks.json` is built with picture stand-ins, so it never `cmp`s equal to `npm run replay` output of the same file. Compare like with like: replay against replay (a scratch `git archive <commit>` copy with `node_modules` symlinked replays the old code), corpus against corpus.
- To prove a test catches a bug: with the fix committed, `git checkout HEAD~1 -- <fix files>`, check the test fails, then `git checkout HEAD -- <fix files>`. For a RED run in another tree, copy the test file into that tree: `node --test <path in your worktree>` imports the code next to the test file, so it proves nothing about the old code (web-compare fixer 7). Keep RED receipts write-once: a run script writing `<name>.tap` overwrote a RED log when re-run after the fix (web-capture fixer 2). A capture drops the own opacity of a box holding only words, so an opacity assertion on a text-only fixture box passes vacuously (`undefined ?? 1`): assert on painted boxes or read the computed value in the page. `node --test` runs test code `tsc` refuses (Json-typed `SNode` fields: `node.opacity - 0.6` is TS2362): typecheck new test code before committing it (web-capture fixer 5).
- "Byte-identical to main" receipts compare `bricks.json` and `warnings.txt`: `bricks.html` is the test renderer's output, so a renderer-only change alters it while the paste stays the same; prove such an HTML difference is the renderer's alone (a normalised diff plus a snap pixel compare at phone widths). When the change adds something a designer could draw (a link on a logo), compare head with base given that drawing (inject a Figma Open link into base's snapshot) rather than listing allowed differences: it also catches the side effects (a linked Div's colour reset, `tap-area`); when a list of allowed differences can't be avoided, pin each one's element or quoted label, never just its message kind (header-bar's receipts let a "menu icon opens nothing" note naming a linked button's arrow through on three real files).
- To see what a layout change does to real files, compare main and the branch element by element: replay each file twice (`git checkout <main commit> -- <src files>`, replay, `git checkout HEAD -- <src files>`), diff the two `bricks.json` by element id (ids are deterministic), then load both replays' `bricks.html` in Chrome and measure the changed elements' rects at every width. The lint misses shape changes (a circle stretched into a pill), so measure before trusting "moves at most 2px". For hover motion, confirm the pointer hit and `:hover`, then measure settled before/after rectangles and matrix translation: an identity matrix differing from `none` does not prove movement.
- For link-scope fixes, prove behaviour independently of appearance: compare decoded before/after screenshot RGBA, then measure every anchor's href and clickable rectangle in Chrome at desktop and phone widths. Pixel-identical pictures can still hide a words-only tap target; assert the intended pill owns the anchor, its drawn icon is inside it, there are no nested anchors, and the enclosing card has no link.
- (Visible window; this desktop's headless Chrome for Testing 156 still drew 60 fps in a background tab, so read side by side in separate windows, `Target.createTarget` `newWindow`: capture-speed planner; but every reading's `Page.bringToFront` then covers a window waiting for a person in the visible run after a human check, which headless window tests never see: hold the others' bringToFront while one waits, capture-speed review 1.) Headless Chrome gives a tab that isn't the front tab no animation frames, and `Page.captureScreenshot` there can wait forever: a tool driving several tabs must `Page.bringToFront` the tab it settles, reads or shoots, and bound every frame wait and screenshot (web-compare's first run hung 7 min). A box below the fold on a scroll-snap page with a fixed full-window video isn't drawn by `captureBeyondViewport`: scroll it into view and clip from the window (web-capture).
- Website-importer browser tests **must** keep every outside address offline: a test drawing a site capture or paste (Justin's scan, the B-Dry stand-in) launches Chrome with `SITE_OFFLINE` (`tools/lib/site-chrome.ts`, as `site:check` does; it is `--host-resolver-rules="MAP * ~NOTFOUND , EXCLUDE localhost , EXCLUDE 127.0.0.1"` plus Google Fonts), else pictures the capture holds no bytes of and widget loaders are fetched from the live site (bricks-icons-site builder: its look test read bdryswi.com and a reviews host, and drew 3 review cards in one run and 4 in the other); and a test Chrome that downloads (`Browser.setDownloadBehavior{downloadPath}`) still writes a hidden `.org.chromium.Chromium.*` temp file in `$HOME/Downloads` first: run it under a scratch HOME with `.cache/chrome-for-testing` and `.cache/chrome-libs` symlinked in (the chrome-f2b wrapper finds both through `$HOME`; importer-app review 1); local fixture origins still load and the iframe keeps its `src` and CSS box (web-embeds planner, probe-blocked.txt). The same switch gives a fixture a real host name: `MAP www.x.test 127.0.0.1` ahead of `MAP * ~NOTFOUND` serves it under an alias, so www.-insensitive host checks in a page-run reader can be mutated (on a plain 127.0.0.1 fixture those mutants are equivalent; panel-embed-code fixer 2, `floating-holds`). A host-based guard (tracking, a tag manager or a CDN on hosts other than the widget's) needs more than the fixture server's two origins: run logging servers on named hosts mapped that way, and when clicking a drawn paste first add a capturing click listener that calls `preventDefault` on `a[href]`, or a rebuilt site link navigates the page away and silently cuts the observation window (panel-embed-code auditor).
- **`npm run compare` picture pairing can silently drop between runs** (Hostinger home: 16, 0, then 34 paired, same heights; `test/web/lib/pictures.ts` `compute()` turns a failed fingerprint into a quiet "broken"): read each width line's `pictures N` and re-run when it is 0 while both sides show photos, before quoting box numbers (demo-1, 2026-11-02).
- A page-compare oracle tested only with self-compares and injected differences builds both sides from the same markup, so freeze side effects and markup-only readings never show: also probe same-look/different-build pairs (overflow hidden on body vs on the section, SVG colour by CSS vs attribute, weight on the block vs a span, an opacity-0 caption vs none) and different-look/same-box pairs (background-size, colours) (web-compare review 1: 31/31 green, 4 P2s). Round 2 found four more the same way: `html,body{height:100%}` + `body{overflow-x:hidden}`, a page-wide SVG sprite `<use>` vs the same icon inline, a block ending in an inline-block word (the plugin's own `span.phone-number`), and two wordless fixed buttons vs one (count-only). Round 3: an inline-block in the middle of a line (a mid-sentence `span.phone-number`, a headline-marker span) where a line ends on it, across the default widths; judge each finding against a word-by-word ground truth (every word's Range rect within 1px on both pages), not section heights. Round 4: block-level boxes (a heading's `display:block` middle line, a flex row of text and a link, an inline-flex button's inner span); round 5: a column-wide stand-in silencing exact pairs inside it. In same-look probes count unmatched blocks too, and make each real difference move only its target, or a neighbour's finding hides the miss. **When the pairing unit (boxes) needs a new stand-in every round, compare the ground truth's own unit directly:** each word's rect against its twin's through the aligned sequence, with page structure only naming and grouping findings; then same look means no finding by construction, and a property test with random structures on both sides pins it (web-compare amendment 1: 74 probes, 0 misses, replacing fixes 3–4's joined and whole blocks). Such a property test must keep the layout invariants real pages keep (a row's columns start at its top; paint belongs to the drawing; a moved section's first words or a non-tallest column's growth change the section height), with each case's preconditions computed from the drawing, never from the matcher's output; so built, it found a real rule gap within minutes (an inline-block far along its line not pushed with it; amendment-1 builder seeds 3, 38). Its generator must also build the structures the reader really builds (the reader made one band per stacked child of an unpainted section, the generator one per section: with the reader's bands 17 of 110 downward moves gave no finding), and every class it leaves out by design needs its own Chrome probe, since a reference taken from the measured items hides the reference item's own move (web-compare review 6); count how often it reaches each class it claims and assert a floor (a 2,000-seed property reached a wrapper band's first block 13 times; a class-preferring one over 6,000 seeds 170, killing its mutants: web-compare fixer 6). What worked: measure each band from where the content above puts it (stayed, or pushed by the band above's last words, whichever is nearer), its own first words only for a whole-band move the next band follows. A push explains only the pusher's explained or reported move: carry each row's and band's unexplained remainder down and report the first word whose sum passes the tolerance, or steps within tolerance add up unbounded (8 sections each 8px lower, exit 0: web-compare review 7); take each word's explained place and a row's lowest explained bottom, never the row's top, or a row of mixed words misreads the line under it (fixer 6). Sorting children into row/stack by one rule leaves a boundary a single move crosses, and the flip swallows the move into an arrangement finding: read "to the right but wholly above or below" from the other page (web-compare fixer 5: 81/937 property moves missed → 0/937).
- A hard seam at a multiple of 4000px page y in a `test/browser/shoot.ts` `screenshotFullPage` shot is its 4000px stitching across a moving widget (two moments), not layout: shoot that area as one capture (scrollIntoView, clip at scrollY) for evidence (after-faq-sections auditor 2). If byte-identical saved HTML yields a small pixel discrepancy, preserve the original pair and its exact changed-pixel locations; use a bounded unchanged-base/same-input capture control before attributing it to source. Write every input's comparison receipt before asserting. One control matching the candidate proves only that input's capture discrepancy; another unmatched input remains a hold. Focused CTA crops and equal geometry are supplementary, never a silent replacement for a failed full-page gate or a font-completeness waiver. If Justin explicitly accepts a retained pixel-proof gap, bind that separate release-only decision to the exact archived pair/hashes, input, width, dimensions, differing-pixel/channel counts, maximum delta and bounds. Keep an unresolved cause UNKNOWN and equality UNVERIFIED, not harmless, pre-existing, fixed or passed. Preserve the red evidence and full expectations; a font waiver does not cover raster proof, and neither waiver covers other/new discrepancies, browser execution, privacy verification or Figma reload/capture/sharing. Update the accepted contract and steer the owner before advancing the first unmet check; do not repeat capture research merely to turn the accepted gap green. For navigation-metadata changes, extend the before/after text proof to source identity → href + same-tab/new-tab + rel for both native Buttons and linked boxes. Exercise sibling isolation, copies and link replacement: the selected action's destination and navigation metadata must travel together, and replacing the destination must not leave stale metadata from its former owner. Preserve the separately approved PDF policy and keep local-renderer proof distinct from installed-Bricks paste/copy-back acceptance.
- Before promoting a descendant link onto its container, inspect all descendant element/run destinations, including absolute and hidden layers; equal hrefs do not erase independent click/provenance boundaries. Keep a positive control with linkless deep decoration so conservative preservation cannot silently disable promotion wholesale.
- When collecting visible link labels, inspect the emitted label for every supported element kind, not just text nodes and children: native Buttons can hold their label in `ir.text`. Test Button-only, text-only and mixed groups sharing one address through conversion, relinking and notes; preserve canonical names, first-seen label order, counts and anchor indices. A metadata-only unit test can pass while real button labels disappear from the user's notes.
- After an interrupted mutation/gate script, compare the exact worktree diff with the committed source and saved mutant before restoring anything; preserve the diff/hashes, restore only the proven mutation, and re-run green. Prefer small isolated source/test copies for later mutations so termination cannot strand a tracked mutant. Preserve partial launch-timeout runs separately and retry unchanged gates; a tool timeout is not itself a source failure. Never edit a script a background bash is still running (bash reads it as it goes): write a new script for the next run (web-capture fixer 7); nor the source a background test run is loading (each test file loads src as it starts): such a run is a diagnostic, never a receipt (web-compare fixer 5). `node --test` options go before the file paths: a `--test-name-pattern=` after them is passed to the scripts and filters nothing. Preflight every explicit test path before a mixed-file command: Node22.23.3 can ignore absent filenames and exit0 after running only the remaining file. Reconcile intended file identities with complete per-file TAP receipts; success alone does not prove the requested population ran (dark-structure-recognition verifier6).
- On a resumed builder, check that evidence paths named in a draft ledger/HANDOFF actually exist: an interruption may save the prose before copying the artifacts. Finish and verify the archive before committing records; preserve real logs and reports, not just their summaries. Keep historical builder archives separate from corrected/integrated finisher proof, and label each tested source/base. Archive original evidence and reviewer probes before cleanup; read the manifest from disk and hash every exact archived target before claiming success. Save the complete report, receipt verdict and committed-source identity before nonessential scratch deletion. If its tool call stalls or is interrupted, report the exact remaining folder and observed outcome without blocking the handback, inventing cleanup success or trying an alternate deletion route (dark-structure-recognition fixer9: committed repair waited819.8seconds on cleanup).
- `snap` takes one comma-separated width argument (`390,1440`), not separate positional widths (`390 1440` silently captures only 390). Assert every requested width's PNG exists before running downstream visual proofs; retain failed diagnostic captures separately. For by-id screenshot crops, exclude zero-size elements hidden at that viewport (drawn-phone copies can come first) and require nontrivial crop dimensions; an image file alone can be a blank 32px crop.
- Qualify layout-measurement ancestor selectors against the actual media: a heading's nearest flex ancestor with multiple children is often its words column, not the words/picture pair. Require a genuine picture in the opposite direct child's subtree, or derive the pair from the exact emitted tree; preserve misidentified probe results as diagnostics, never geometry acceptance.
- Count actual label lines from nonblank text-node Range rects, not a parent's full Range: icon/inline-element boxes can have different tops while the label stays on one line. Preserve the raw over-count and qualify the corrected reader before calling a header label wrapped. For tracked words, a Range includes trailing letter spacing that a negative end margin gives back to flow: qualify apparent overflow against painted glyph bounds and the same-machine baseline, and prove the reader rejects a deliberate glyph displacement. Conversely, keep whole-row wrapping separate from one word's baseline correction.
- For a kept hero row's word cap, compare planned and real border-box column widths before changing the ink estimate or its safety pad. CSS flex shrink scales the inner bases: a picture frame's padding/border do not shrink, so a drawn outer-width ratio can overstate the words' room. Share the corrected scoped calculation between the keep decision and layout/type reader, retain ordinary/grid/portrait controls, and prove a whole-word Range regression with the exact old-source causal revert. A remaining complete-word three-line heading is a separate phrase-fit contract question, not permission to increase the approved padding.
- When an approved whole-word oracle covers every original width, also test the inherited break backstop after upright stacking at 320px: a cap limited to kept tiers can restore a larger portrait size while `break-word` still cascades. Reuse the existing word cap and the planner's smallest-phone slot for a demonstrated split; do not add phrase fitting or shrink an already accepted complete-word heading. Keep shorter-heading unchanged-size and portrait-stack controls. For breadcrumb baseline checks, group rows by their actual flex item boxes, not displaced ink, so a vertical-offset mutant cannot invent its own row. Font Range ascent/descent may extend outside the line-height box without clipped glyphs; check column/clipping bounds rather than treating that box as an ink mask.
- A hero share guard must not use drawn-width ratios for FILL/flex-basis:0 or intrinsic-width columns: Chrome can give the picture or words zero room. Return an explicit unknown share and retain the ordinary row policy when allocation cannot be proven; the keep guard and type-room reader must share that result. Exercise words-only fill, media-only fill, both fill and fixed/hug controls. Attribute extra desktop/laptop failures against exact main before expanding a tablet/landscape fix.
- No whitespace or Unicode script/category whitelist is proof of a browser-unbreakable word: Han/kana/Hangul, soft hyphens, zero-width spaces and fullwidth Latin/digits may legitimately span lines; `Script=Latin` and `Decimal_Number` include fullwidth ID-class characters. Prefer a closed, audited AL/NU alphabet with attached proven nonbreaking marks, leaving all uncertain forms on main's geometry; do not trim away leading/trailing separators or compatibility-normalise source text. Pair Scene checks with ordinary non-auto-layout captions and real two-line Chrome calibration, asserting both paddings/parent footprint/following position, plus composed/decomposed Latin and Services repair positives. Check halfwidth and mixed-width controls too, and audit accepted ranges against Unicode LineBreak/EastAsianWidth rather than another incomplete blacklist.
- Before broadening a text-normalisation repair from a malformed Figma box, add negative controls for legitimate natural wrapping outside the reported component: ordinary auto-height words, different font widths, narrow containing boxes and already-correct sibling baselines. Compare unchanged base and candidate under identical fonts and widths, then revert only the proposed normalisation to establish causality; a one-case breadcrumb repair and byte-identical existing corpus do not establish safety for other designs. Preserve the failing candidate and restored-candidate receipts for independent review rather than recording an unresolved regression as a proven fix.
- If several greedy word groupings reproduce the same Figma ink width and line count, use the most cautious admissible width estimate rather than first-match iteration order. Exercise the real-font browser matrix: average ink and a longest-word cap still do not guarantee a multi-word heading avoids intra-word breaks or one-word-per-line layouts. Keep an unmet stronger visual oracle red instead of silently changing its font, fixture or shrink policy.
- For opt-in row/picture geometry tooling, exercise the public `runLint` wrapper with independently specified fit expectations; do not infer intent from the same measured rectangle. Pair clipped-image findings with tiny screenshot-pixel/hit controls, prove scroll reachability by actually scrolling, and reject unsupported clip geometry rather than treating it as a pass. Keep intentional-crop/no-contract legacy controls unedited. Prove CLI diagnostics independently of output changes with matched-width payload/full-HTML/PNG hashes and separate before/after exit receipts; a multi-width font test must make an early document incomplete and a later reload complete so it can catch a lost accumulated failure.
- For horizontal scroll-reachability checks, compute the reachable extent from the scroller's computed direction: RTL at `scrollLeft=0` starts at the right edge and its scroll range extends negatively. Prove the public wrapper with actual LTR/RTL scrolling and hit-testing at initial/intermediate/end offsets; retain unreachable start-side overflow and out-of-clip viewport controls in both directions. Exempting every negative rectangle hides real clipping, while a left-origin range both falsely clips reachable RTL art and falsely exempts unreachable right-side overflow.
- Programmatic `read_file` can return `status: unchanged` with no `content`. Reuse the earlier confirmed read rather than indexing `result['content']` blindly; an unchanged read is not a failure or permission to bypass a protected-file write denial.
- Recapturing a saved corpus baseline after changing capture policy: keep the original report/log/pastes/HTML, label the new report a **matched-policy recapture**, and assert the whole rendered HTML is byte-identical before comparing. Parsing `stableJson` sorts property keys and can reorder generated CSS, so a parsed saved paste alone does not reproduce the original HTML. Reuse the original HTML or reproduce its original insertion order and verify exact equality. Preserve non-comparable runs too: a failed external Google stylesheet can leave a family absent from both `fontStatus.loaded` and `failed`, so compare loaded-family sets, not only `failed: []`.
- **Run long browser gates outside the foreground cap** (a Claude Code subagent never ends its turn to wait, which counts as finishing: it blocks in polls under 170 s each, e.g. `timeout 160 bash -c 'while [ ! -f <exit-file> ]; do sleep 3; done'` repeated (Claude Code moves any foreground command to the background after ~180 s whatever its timeout), or relies on the background task's completion notice, or waits on a driver with `timeout 170 tail --pid=<pid> -f /dev/null` (no CPU; web-panel rebase), never `read -t N < /dev/zero`, which spins a core and skews timing gates): if a full suite can outlive one terminal call, start it as a tracked background process and wait with `process_manage`, or split it into complete file groups that preserve total coverage. Keep the complete TAP log; a terminal timeout is not a test verdict. On the WSL desktop start long file-by-file drivers with `setsid --fork` and wait on their final marker: two started with the Bash tool's `run_in_background` were stopped together after about 4 minutes (exit 144, no memory kill) (staging-fit-renderer builder 2).
- Reconcile owned test processes after an interrupted browser run before retrying. Never `pkill -f <pattern>` from the Bash tool when the pattern is in that command line: it kills the tool's own shell (exit 144); kill PIDs taken from `pgrep`, the shell excluded (site-shared-styles review 3). A `setsid --fork` runner whose tests run under `systemd-run --user --scope` can't be stopped by `kill -- -<sid>` (its Chromes sit in other groups): list the session's PIDs (`ps -eo pid=,sid=`) and kill each (site-shared-styles rebase fixer). Before signaling a saved PID, verify this exec can see its recorded process tree: isolated exec invocations can reuse PID numbers. If it is not visible, interrupt through the owned tracked session handle (`write_stdin` in Codex), and distinguish the observed controller exit from an unobserved child exit. A child agent's terminal-session ID may be unknown to the coordinator while its browser still runs: verify a fresh read through the owned loopback CDP endpoint from the receiving executor before relaunching or calling the handoff ready. Where visible, list roots with `ps -o pid,ppid,command` and match the recorded launch/process tree, exact run-owned `--user-data-dir` and work area. PPID 1 alone does not prove ownership; terminate only proven owned orphans within current permission, never every Chrome/Node process or another worker's browser. Read back absence of those owned roots, not global browser absence. Kill by PID, never `pkill -f <profile>`: the shell running it has that pattern in its own command line and dies first (exit 144, the rest never runs). Keep logs and termination receipts; process termination does not authorize deleting profiles, evidence or existing folders. Apply the task's separate cleanup scope to any file removal, because shared-host processes and temporary-folder names are not exclusive ownership markers. Never `pkill -f <pattern>` from a tool's shell: the pattern is in that shell's own command line, so it kills itself (exit 144) before the next command; stop processes by the PIDs of their own profile or TMPDIR path (panel-embed-code review 2).
- A base `git archive` used for a by-name browser comparison needs `npm run build` first: the panel browser tests read `dist/ui.html`, which isn't in git, so an unbuilt base fails every panel test and can hide a head failure (header-bar fixer 2).
- `document.elementFromPoint`/`elementsFromPoint` take viewport coordinates: a target below the fold returns null (an empty list) and looks hidden, clipped or "not painted over" (scroll the section into view first; a `pointer-events: none` target needs pointer events on during the probe, faq-art builder). For reachability/paint checks, move the page's own scroller to an attainable position clear of fixed/sticky headers and remeasure; an arbitrary centre scroll can put reachable words behind a tall header (landing-page-six builder: eight apparent phone paint failures cleared without a product change). Preserve the failing capture and qualify the reader with a separate sticky-header fixture. `scrollIntoView` can also move clipping ancestors/carousels; follow `live-site-reading.md`'s scroll-offset rules rather than making hidden content falsely reachable. It also hits invisible boxes: CTAs, photo cards and carousel cards fade in on load (0.8 s delay + 1.5 s), so a shot under ~3 s after load shows them missing while hit tests pass; wait ≥ 3 s (or reduce motion) before shots.
