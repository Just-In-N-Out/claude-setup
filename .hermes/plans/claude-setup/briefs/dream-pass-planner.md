2. **Evidence kinds.**

Nothing inferred from silence or from accepting one result. A paste counts only when it is the whole message; a paste inside a typed message is ignored.
   - (b) What agents corrected: review findings (`~/.hermes/plans/*/evidence/**/review-<n>/review.json`, keys `round, scope, from, head, findings[{id, severity, file_line, claim, scenario}]`; 208 files, 711 findings today) and failed ACs (`ac.json`, 303 files). `skill_lessons` are already saved live by the main session; use them only to avoid duplicates. In-session agent retries are measured in a hand trial first, not in v1.
3. **The bar.** Justin's explicit correction or stated decision counts at once. Everything else needs the same thing in two or more sessions or stories; candidates seen once wait in a pending list that survives across runs. Tool output may prove something failed or passed, never supply a rule's wording. A fix that worked by weakening a check (skip a test, bypass a guard, force) is never learned automatically: it goes on a list for Justin. Anything that would loosen a safety rule (push, authorship, approval, guards) is never applied automatically: same list. Justin's statement wins over an agent lesson; a newer statement of his replaces the older entry (dated), never stacks. Never copy keys, tokens or passwords, or personal details about other people.
4. **Scope of a note.** Narrowest place first: the project's memory notes or project skill. Global `CLAUDE.md` only when stated as general or seen in two projects.
5. **Targets (all tracked by the setup repo `Just-In-N-Out/claude-setup`).** `~/.claude/CLAUDE.md`, `~/.claude/project-docs/*/CLAUDE.md`, `~/.claude/projects/*/memory/**`, Justin's own skills under `~/.hermes/skills/**` (`~/.claude/skills/*` are links to them), and the library-linked skills too (Justin: "you can edit them. Never a target: `~/.codex/AGENTS.md` (generated from `CLAUDE.md`), anything under `~/Leorna/`, transcripts, evidence folders.
6. **Repeat-mistakes files.** Three files of one shape: `leorna/references/repeat-mistakes.md`, `figma-to-bricks/references/repeat-mistakes.md`, and a general one at `feature-dispatch/references/repeat-mistakes.md` (also holds setup stories' mistakes). Each entry: the mistake (count, stories), "build it this way" (builder and fixer), "check for it" (reviewer). Grouped by area, most frequent first, about 15 KB per file (roughly 60 entries, Justin: "more than 20"). An entry retires when the mistake has not come back in about 10 stories; it moves to the general file when seen in both projects. A repeat despite being listed becomes a proposal in `~/.hermes/plans/claude-setup/enforce-backlog.md`, not more wording. Builders, reviewers and fixers must all read the file for their project plus the general one (one pointer line in the project skill and in the feature-dispatch brief rules). The dream keeps its own tally of mistake kinds (kind, count, stories); agents never read the tally.
7. **One run.** (1) `sync.sh pull`, abort on CONFLICT. (2) A script, no model, extracts new typed messages per session plus the last 1,500 characters Claude said before each (marked context, not evidence) and the new review findings and AC failures as one line each; nothing new → exit at zero tokens. (3) One helper per session with new typed text, reading only its digest, no tools, returns findings each quoting one typed message; one more helper sorts new review findings against the tally. (4) A script checks each quote is verbatim in a typed message of that session and applies the bar. (5) One editor edits a copy only; it sees findings, never transcripts. (6) One checking agent sees only the diff and the evidence and answers: was a specific fact lost, and does every change trace to evidence? A "no" means nothing goes live. (7) A script checks size budgets (a file over budget may only shrink), secrets (gitleaks), per-run change caps, a canary list of exact facts that must still be present, that no target changed since the copy (hashes), and the library clone's 0 commits. (8) Apply to the live files, one commit `dream(<time>): …` in the setup repo, pushed to `main` of `Just-In-N-Out/claude-setup` the way `sync.sh` pushes (its lock, its credential helper; other sessions' pending edits must not land inside the dream commit). (9) Append the log entry; cursors advance only after the commit.
8. **Live without review.** Justin: "Just merge to live files." The revert path is reverting the dream's commit. A backup tag `pre-dream-2026-11-09` (commit `fafe0ac3`) is already on GitHub.
9. **Write ledger (Justin's hashing idea).** A hook on Write and Edit records, for every target file any agent edits: path, sha256 after, session id, agent id, time. The copy-time hash against the apply-time hash is the "changed underneath" check in step 7. Say whether Codex's hooks can feed the same ledger.
10. **Marker.** Per session (22 of 83 sessions span more than one day): last processed line per session, kept in a state file; skip a session modified in the last 30 minutes. The log is human-readable and also states the marker in words.

Decide how the headless calls avoid Justin's interactive hooks (sync pull, orchestrator-guard, nudges, lessons gates) and tool access, and verify the flags against `claude --help` on this machine rather than trusting this brief.
