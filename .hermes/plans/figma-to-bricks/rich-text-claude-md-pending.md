- **Words elements hold a `<p>` since rich-text** (Rich Text, `div.brxe-text > p`): browser tests measure the inner `p` (`el.querySelector(':scope > p') || el`); `Range.selectNodeContents(el).getClientRects()` also returns the `p`'s own box (one line too many) and `el.firstChild` is the `p`, not the text node (rich-text builder, 2026-11-04).
- Decision (Justin, 2026-11-04, on the designer's "rich text for paragraphs": "I do not want it for paragraph i want it for everything"; chose in a question): **every text is Rich Text except headings** (Bricks Heading stays, with its tag); **a text that is all one link is Rich Text inside a Block that carries the link in Link to** (both designer notes hold); no Basic Text is emitted.
- **Rich Text HTML always goes through `emit/rich-text.ts` `asTyped`** (rich-text fixer 1, 2026-11-04): Bricks prints Rich Text through `parse_editor_content` (wptexturize + wpautop), so `asTyped` writes the designer's quotes, dashes, dots and `x` as numeric entities and breaks `<br><br>` with `<wbr>`; `test/browser/editor-content.ts` models it in the renderer. A saved edit in Bricks' rich editor may turn the entities back into plain characters.
