## How we test a story here (agreed with Justin, accepted by Christian)
- Commands: `make test` (everything, race detector), `go test ./internal/web -run <TestName> -v` (fast loop), `make check` (full CI gate: workspace, contracts-check, fmt, vet, test, lint, govulncheck, gitleaks, build), plus `bash ./scripts/test-module-add.sh`. Needs `LEORNA_TEST_DATABASE_URL` set or Postgres tests silently skip; confirm they ran with `-v`. Under heavy load (about 28 load average on the desktop) `internal/library/upstream`'s `TestCloneStopsAtItsDeadlineWhenTheServerStalls` can fail with "git never connected": rerun it alone before blaming the story (86bcxnymy fixer 1: 3 of 3 passed alone). `make check` (its `contracts-check` regenerates and restores `packages/contracts/controlplane.gen.go`) and `test-module-add.sh` (a `.module-add-test.XXXXXX/` dir joined with `go work use`) briefly write into the tree they run in, so a read-only verifier or auditor runs them in a detached copy at the same SHA; `go test` alone is safe in the story worktree, which `ac-check.sh` needs clean (901v v3 merge verifier, 2026-10-24). A quick check outside `make check` must name the workspace module too: root `go build ./...`/`go vet ./...` skip `packages/contracts` (`go list ./... | grep -c packages/contracts` is 0), so add `./packages/contracts/...` (86bcm901r #99 fixer).
- Since PR #94 (main `da8a4b0`, 2026-10-29), CI's quality job also builds the production image and runs "Verify packaged content scanner" (`docker run --rm --entrypoint /usr/local/bin/gitleaks <tag> version` must print `8.30.1`), which `make check` doesn't. The local equivalent is `docker build --file Containerfile --tag <own tag> .` in a detached copy, then that `docker run`; about 2 min on the WSL desktop. Add `--no-cache` and check that the `RUN go build` step says DONE, not CACHED: a cached build only proves an earlier build of the same context worked (901a verifier 3). Remove your tag afterwards. Trivy, Helm lint/template and OpenTofu remain CI-only there (86bcm901a bring-main-in 2).
- Test first, always: write the test, watch it fail for the right reason, then write the code (superpowers TDD skill).
- One subtest per acceptance criterion, named after it, in a Postgres-backed HTTP test modelled on `TestTeamsAPIWithPostgres`: throwaway schema + `ApplyMigrations`, create users (`ResolveOrCreateGoogleUser` = new tenant admin; `CreateUser` in `store.WithTenant` = member), insert session rows, set the two cookies. "UI component tests" in stories means asserting on rendered HTML; there is no component framework.
- Always include: member gets 403, wrong CSRF gets 403, unknown and other-tenant IDs get 404 (store answers not found, never forbidden; exception: a desktop-client API call from another company's client gets 403 `TENANT_MISMATCH` from `requireClient`, `internal/web/client_auth.go:140-162`, since one deployment is one company, so prove the store separately with `ResolveForProject(otherTenantCtx, …)` → `store.ErrNotFound`; desktop fixtures set `handler.discovery`, with `BackendUrl`/`discoveryHost` = the test server once 86bccndx6's canonical-host check lands; 86bcm928t planner), unauthenticated HTML page gives 302 to `/v1/auth/google/login`, and a tenant A vs tenant B isolation test. Store-level test covers the same boundaries without HTTP. Handler branches a real DB can't reach get a small fake repository test.
- Lessons from the review: scope HTML assertions to the element (e.g. each tile block), not whole-body `Contains`; `html/template` escapes a `+` in text as `&#43;`, so a diff's `+` prefix or `@@ -a,b +c,d @@` header passed as data never matches a literal `+` in raw HTML: write those as template literals (86bcm901z builder); read repeated rows (supporting files) by a stable key from each row's own markup, never by position: `itembuilder.validate` sorts `in.Files` in place through a by-value `Input` (`validate.go:88`, shared backing array), so the edit page's row order can differ from the submitted order and an index check passes on the wrong row (86bcm901z fixer 3); vary fixture values so one value can't mask another; assert JSON by unmarshalling and checking the key set, not substring search; add new tables to both lists in `TestMigrationRoundTrip` and to the `resetDatabase` drop list; `ApplyMigrations` checks each applied migration's sha256(up + NUL + down) on every startup, so editing an unreleased migration in place makes any database that ran the old file refuse to start ("migration N checksum mismatch"), not keep the old rule: recreate those databases (86bcm901r verifier); prove a hardened assertion can fail by temporarily mutating the code, then restore it.
- Mutation checks: scope the edit to the function under test (the same `pgErr.Code == "23505"` line exists in several store functions; a replace-first hit the wrong one). `internal/store/postgres`'s `seedBaseStore` only resets the DB and migrates, never `EnsureSeedBase`, so a mutant that lets shared seed rows into a shared-row query survives every store test; run such probes in `internal/web`, whose fixtures load the seed base (86bcm901r review-1: R1-M19 survived in store, killed by AC1 in web). Admin principals skip the team-membership check on project reads (`internal/web/projects.go:73`, also `withProject`), so an engineer-facing desktop test that mints its token for `fixture.admin` never runs the member path: mint it for `fixture.member` added to the team (86bcm901r auditor 2: AC2 used the admin token; a member probe passed and got 404 for another team's project). A "run it concurrently" test after the row already exists never races; force the race with an uncommitted insert in another tx and wait for `pg_stat_activity.wait_event_type='Lock'` (see `waitForLockWait` in `pack_versions_test.go`). Match the waiting query loosely (`LIKE '…%FOR UPDATE%'`), not by exact SQL text, and wait for the blocked goroutine on every exit (WaitGroup in the deferred rollback): an exact match reports "never waited" after a harmless SQL change, and the leaked goroutine later commits into other subtests' row counts (901w `waitForPackLineageLock`, commit `bede133`). For an advisory lock a loose poll also sees other databases and other tests' waits on the same key (advisory keys are per database, so the per-schema fixtures share them), and a delete-the-lock mutant survives by timing: run the code under test on its own pool with a unique `application_name` and poll `application_name=$1 AND datname=current_database() AND wait_event='advisory'`, creating that pool before the deferred rollback, since `pgxpool.Close` blocks (86bcm901r M3). chromedp console captures: after clicking a submit that redirects (303), Poll/Evaluate fails with "Inspected target navigated or closed (-32000)", and `WaitVisible` on an element both pages share (edit page → edit page) can match the old page. What worked first time: an `ActionFunc` loop calling `chromedp.Evaluate` every 250 ms, ignoring errors while the page navigates, until content only the new page has is there and `document.readyState == 'complete'` (up to 30 s; 901w verifier's `waitFor` in `evidence/86bcm901w/verifier/capture-main.go`). The console's CSP blocks an in-page `fetch()` run through `chromedp.Evaluate` ("Failed to fetch"): check what a save stored with `docker exec … psql` on your own demo `_test` DB, or call the API from Go with the browser's cookies; a failed in-page fetch mid-run leaves a half-made pack and the demo DB has to be reset (901w verifier 2).
- Web test fixtures: `newPackFixture` (`internal/web/packs_test.go`) does not load the seed base. `EnsureSeedBase` (`internal/store/postgres/pack_versions.go`) inserts each new embedded seed version (tenant_id NULL) with created_at = now at startup, and tenant edits keep the seed's name, so any "newest version per pack name by CreatedAt" rule lets a seed release displace a tenant's edited pack: test the seed-plus-edit mix (86bcm902w review 1, R1-1). `EnsureSeedBase` also has no older-binary guard (`ensureStarterPacks` refuses `Older`): it inserts the embedded seed version whenever that version is missing, so a rollback on a database a newer binary created writes the older seed last; a "current seed = newest role-less shared row by created_at" rule then names the older seed, so use the running binary's `DefaultSeed()` version when a story needs the current seed (86bcm902w review 4). It gives a throwaway schema, admin/member/other-tenant principals, `login`, `get`, and exposes `handler` + `pool`. `newSetupFixture` (`setup_test.go`) adds the real `provision.Service` over the mocked cloud `auditWorkflowProvider` (`cloud_audit_test.go`, `fail` toggle, returns endpoint outputs) and `connectScaleway` (stores a credential via `secret.Vault`, like the launcher). Pack Assignments renders its version options only inside `{{if .Teams}}` (`pack_assignments.go:178`), so a test that checks an option creates a team first (86bcm901r fixer 2). `pack.ItemEdit.Files` needs paths in strictly increasing order (`internal/pack/pack.go:222`), or `VersionService.CreateItem` fails with the misleading "pack item supporting file is invalid: invalid organization request": sort fixture files by path (86bcm901z review 3).

## CI secret scan scans every branch
CI checks out with `fetch-depth: 0` and runs `gitleaks git`, which scans ALL refs, so a flagged commit on anyone's branch fails every PR's "Scan repository for secrets" step. Locally `make check` only sees the branches you've fetched. To reproduce: `git fetch origin && gitleaks git --redact -v`; to check only your PR: `gitleaks git --redact --log-opts="origin/main..HEAD"`. The config is `.gitleaks.toml` from the PR's merge commit, so an allowlist only helps once it's on main. A "Re-run jobs" reuses the old merge commit; a new push is needed. First hit 2026-09-26: PR #47 failed on two fake test JWTs in Christian's PR #46 branch `feat/console-session-capture` (`internal/console/extract_test.go:66`, `internal/console/capture/capture_test.go:46`).
