After GRO desktop (2026-10-07) the user chose a separate milestone for phones of free-floating designs; plan
`docs/plans/2026-10-07-gro-phones.md`, built 2026-10-07 (build .20); the user's phone paste check of GRO is owed.

The user's decoration choices (asked 2026-10-07, all four answered):
- big outline words layered over other things: their own line where they read, shrunk to fit; a word across a photo
  goes just above it;
- heading pieces drawn as pictures that overlap/stagger shrink together as one picture;
- landscape drawings shrink to the phone's width at their edge; all-over patterns (stars, contours, rain) keep covering;
- big decorative numbers go right above the item they label;
- a sideways label beside a heading turns upright on phones, a line above it.

The user asked whether the fixes are general (2026-10-07): every rule must be detected from structure and checked
against all five corpus files before building (scratch simulations), never keyed to GRO.

**Why:** the user judges phones by how they look in Bricks and wants logic that works on any design.
**How to apply:** follow these choices for any free-floating design; ask before reversing one. See [[v2-rewrite]].
